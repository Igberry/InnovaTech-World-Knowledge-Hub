**Goal:** Learn the categories of tools a VA uses, set up a task board you will actually run, and build
one simple automation, while avoiding the trap of collecting tools you never use.

## Learning Objectives

By the end of this week you can:

- Name the main categories of VA tools and what each is for
- Set up and run a task board for one or more clients
- Work well in shared documents (comments, versions, structure)
- Build one simple automation to save repeated work
- Choose tools by the job, not by the hype

## Tools / Accounts Needed This Week

- A task board: Trello, Notion, or ClickUp (free tiers)

## Lesson 1: Think in categories, not brands

New VAs drown in tools. The cure is to think in **categories**. There are only a handful, and each has
several free options. Learn one tool per category well; you can switch brands later in an afternoon.

| Category | What it does | Common options |
|---|---|---|
| Task / project board | Track what needs doing and its status | Trello, Notion, ClickUp, Asana |
| Documents | Write and share text, notes, SOPs | Google Docs, Microsoft Word online |
| Spreadsheets | Data, trackers, simple reports | Google Sheets, Excel |
| Scheduling | Let people book time | Booking-link tools (free tiers) |
| Communication | Chat and calls | A chat tool, Google Meet, Zoom |
| Storage | Keep and share files | Google Drive, OneDrive |
| Time tracking | Record hours per client | A free tracker, or this course's CSV |
| Password manager | Store and share access safely | A reputable password manager |

> **Tip:** When a client uses a tool you do not know, do not panic. Say "I will get up to speed on that
> this week." Most tools in the same category work the same way. Your transferable skill is knowing what
> the category is for.

## Lesson 2: Run a task board

A **task board** (or Kanban board) shows work as cards that move through columns as they progress. A
simple, powerful setup:

- Columns: **To do → Doing → Waiting → Done**
- One card per task, with a clear title ("Draft March newsletter"), a due date, and a short description
- The **Waiting** column is the secret weapon: it holds tasks blocked on the client, so nothing is
  forgotten and you can see at a glance what you are waiting for

For multiple clients, either one board per client (cleaner) or one board with a label per client (fewer
places to look). Start with one board per client while you learn.

A good board replaces a dozen "did you do X?" messages. The client can glance and see everything, which
builds trust and cuts interruptions.

> **Rule of thumb:** If a task is not on the board, it does not exist. Capture every task as a card the
> moment it arrives, before you forget it.

## Lesson 3: Work well in shared documents

Much VA work happens in shared docs. Doing it well is quietly professional.

- **Comments, not edits, on someone else's draft.** Suggest with a comment; do not silently change their
  words unless asked.
- **Version history.** Shared docs keep old versions. You can always go back, so you never need "final
  final v3" files.
- **Structure.** Use headings so a long document has a clickable outline. Clients notice tidy documents.
- **Share carefully.** Give the right access (view, comment, or edit) to the right people. Do not make a
  private client document public.

> **Privacy:** Check sharing settings every time. "Anyone with the link can edit" on a client's document
> is a real risk. Share with named people, at the lowest access that works.

## Lesson 4: Simple automation

**Automation** means getting a tool to do a repeated task for you, so you do not do it by hand every
time. You do not need to code. Start with the small, safe wins:

- **Email templates / canned responses** for replies you send often
- **Saved reply snippets** in a chat tool
- **Calendar booking links** so people schedule without emailing you
- **Rules/filters** that auto-label incoming email (e.g., receipts go straight to a Finance label)
- **Recurring tasks** on your board that reappear every week

There are tools that connect apps together (when X happens, do Y) for bigger automations. They are
powerful, but start with the built-in automations above; they cover most of what saves a VA time, with
no risk of a mis-wired automation doing something unwanted.

> **Warning:** Test any automation on a safe example before you let it touch real client work. An
> automation that files or deletes the wrong emails can cause real damage. Start small, watch it work,
> then trust it.

### Common mistakes

- **Tool overload:** signing up for ten tools and mastering none.
- **Not using the Waiting column**, so blocked tasks vanish.
- **Editing someone's draft directly** instead of commenting.
- **Over-sharing documents** with "anyone with the link."
- **Automating before testing**, then trusting a broken rule.

## Practice Exercises

1. Set up a task board with the four columns for one fictional client. Add eight cards with due dates.
2. Move cards through the columns to reflect a day's progress, using the Waiting column at least twice.
3. In a shared doc, practise leaving three comments and restoring an earlier version.
4. Create one email template and one auto-label rule (filter) in a practice inbox.
5. Set up a recurring weekly task on your board (e.g., "Send Friday report").
6. Write a two-line note you would send a client explaining how to read the shared board.
7. List the tool you would learn first in each category, and why.

## Weekly Assignment (Due Before Week 5)

Build a **working toolkit** for the fictional client Ada:

1. A **task board** with the four columns and at least 8 realistic cards (titles, due dates, a few in
   Waiting), shown by screenshot or export
2. One **shared document** (an SOP or note) with a clear heading structure and one comment
3. One **built automation** (email template, filter, or recurring task), described with a screenshot
4. A short **note to the client** explaining how to use the board

### Grading guide

| Criteria | Weight |
|---|---|
| Task board is clear, realistic, and uses Waiting well | 35% |
| Shared document is well structured and correctly shared | 20% |
| A real, sensible automation is built and tested | 25% |
| Client note explains the board simply | 20% |

### Definition of done

- [ ] Board has four columns and 8+ cards with due dates
- [ ] At least one blocked task sits in Waiting
- [ ] Document has headings and correct sharing
- [ ] Automation works and is described clearly

## Facilitator Notes

The main risk this week is tool overload and learners feeling behind because they do not know a specific
app. Keep returning to categories: the transferable skill is knowing what each category is for. Make them
build, not just watch. For automation, insist they test on a safe example first; a horror story about a
filter that deleted real emails lands the lesson. Let learners choose one task board and go deep rather
than sampling all three.

## Self-Check Questions

1. Why is it better to think in tool categories than in specific brands?
2. What does the Waiting column on a task board prevent?
3. When editing someone else's document, when should you comment rather than change the text?
4. What is one safe automation a new VA can set up, and why test it first?
