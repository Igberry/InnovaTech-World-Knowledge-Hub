**Goal:** Run a client-style project end to end: a discovery call, a safe shoot, three edit versions through two documented revision rounds, and an organised hand-off. You role-play and produce the whole job this week.

## What you'll be able to do

- Ask the discovery questions that stop a project going wrong
- Turn answers into a brief the client approves before filming
- Plan a safe shoot with consent and an event-day checklist
- Produce versions 1, 2 and 3 from two rounds of feedback
- Control revisions with time-coded notes, version names and a change log
- Prepare an honest title, thumbnail, description and delivery note

## Before you start (about 10 minutes)

- Open the [fictional choir promo brief](/downloads/video-editing/client-brief-fictional-choir-promo.md), the [client brief template](/downloads/video-editing/client-brief-template.md), the [discovery questions](/downloads/video-editing/discovery-call-questions.md) and both revision notes.
- Warm-up: write three questions you would ask before quoting a real project. These set up your discovery call.

## Try it 1 - Run a discovery call and build the brief

**Why it matters:** editing before you know the audience, message and destination wastes the whole shoot.

**Do this now:**
1. Role-play the discovery call using the [discovery questions](/downloads/video-editing/discovery-call-questions.md). Ask who it is for, what the viewer should know, where it runs, what facts are approved, the deadline, who reviews, and what success looks like.
2. Fill the brief: audience, key message, deliverables, length, destination, approval process, location, participants, captions, assets, licence responsibilities, review rounds, hand-off.
3. Mark every unknown fact as a question. Do not invent it. Get the brief approved before filming.

**You've got it when:** your brief is complete and every gap is flagged for the client.

## Try it 2 - Plan a safe shoot with consent

**Why it matters:** attendance is not permission. A sensitive setting needs the organiser's rules followed.

**Do this now:**
1. Build a safe event-day checklist from the [event-day checklist](/downloads/video-editing/event-day-checklist.md): filming areas, prohibited areas, approved participants, schedule, power, backup.
2. Identify one no-film area and one person or detail that must stay private.
3. For any real subject, get permission for the specific use. For children, get guardian permission and venue rules; the safest default is not to film children. Never expose an address, badge, screen or payment record.

**You've got it when:** your plan names where you can film, where you cannot, and who has consented.

## Try it 3 - Produce version 1

**Why it matters:** V1 is a review copy for one decision-maker, not a finished film. It exists to gather feedback.

**Do this now:**
1. Edit version 1 from permitted footage (fictional choir, Fresh Bites, or your own permitted clips).
2. Add a timecode slate so a reviewer can point to an exact moment.
3. Name it clearly, for example `ChoirPromo_v01_review.mp4`, and keep project, notes and exports together.

**You've got it when:** a labelled V1 with visible timecode is ready to send for review.

## Try it 4 - Apply two revision rounds with a change log

**Why it matters:** controlled revisions are what separate a professional from an amateur. A change log proves what you did and why.

**Do this now:**
1. Apply [Round 1 notes](/downloads/video-editing/revision-notes-round-1.md) to make `v02_review.mp4`. For each note, mark it applied, adapted, declined or needs clarification, and explain in the change log.
2. Apply [Round 2 notes](/downloads/video-editing/revision-notes-round-2.md) to make `v03_final.mp4`. Compare v1, v2 and v3 for unintended changes.
3. If a note would make the story inaccurate, break a licence, expose private info or exceed scope, decline it calmly and propose a safe alternative. A new concept is a new scope request, not a free revision.

**You've got it when:** three distinct versions exist and every note has a logged decision.

## Try it 5 - Package the delivery

**Why it matters:** a clean hand-off with honest titles and a delivery note is what gets you hired again.

**Do this now:**
1. Draft an accurate title and a thumbnail concept that is readable small and not misleading.
2. Write a description with the subject, approved sources and a clear next step.
3. Create a delivery note listing files, version, destination and any known limitation. Ask how long raw files should be kept.
4. Check current platform requirements before any publish, and never upload a client project to a personal or public account without written approval.

**You've got it when:** your delivery note and title describe the real video, nothing inflated.

### Watch out for

- Editing before the client confirms audience, message and destination
- Assuming attendance means permission to publish every face
- Taking conflicting feedback without one approver
- Treating a new concept as an included revision
- Overwriting V1 before V2 or V3 is verified
- Reusing a client logo or footage in a portfolio without approval

## This week's build: a client job through two revision rounds

Use the fictional choir promo or Fresh Bites brief.

1. Plan, shoot or select permitted footage, and edit version 1.
2. Apply both supplied revision rounds to produce v2 and v3.
3. Submit all three exports or review files, a change log, and a one-page project report.
4. If you cannot shoot safely, use your own permitted footage or complete the planning and edit with a facilitator-approved local set. This course is not legal advice; the agreement outline is a learning aid, not a contract. Do not collect passwords or payment details.

### Grading guide

| Criteria | Weight |
|---|---|
| Meeting the brief | 25% |
| Editing quality | 25% |
| Revision handling and change log | 25% |
| Professionalism of documents | 15% |
| File naming and delivery | 10% |

### Definition of done

- [ ] The brief is complete and all unknowns are marked for clarification.
- [ ] Version 1, version 2 and version 3 are distinct and labelled.
- [ ] Both revision rounds have a documented response in the change log.
- [ ] Permission, licence and privacy checks are complete.
- [ ] The project report and delivery note identify limitations honestly.
- [ ] No version is published without approval.

## Extra quick wins (optional)

- Rewrite one vague note ("make it pop") as an actionable, time-coded request.
- Build one reusable title template with clearly labelled placeholders and no client assets.
- Practise declining one out-of-scope request politely in writing.

## Mentoring Session Plan (90 min)

| Time | Activity |
|---|---|
| 0-10 min | Review project boundaries and subject permissions |
| 10-25 min | Role-play discovery and clarify the brief |
| 25-40 min | Build shot plan, schedule and event safety checks |
| 40-55 min | Demonstrate time-coded feedback and version naming |
| 55-70 min | Apply one revision and update the change log |
| 70-82 min | Draft title, thumbnail and delivery note |
| 82-90 min | Review assignment, approval and retention rules |

## Facilitator Notes

Use only the fictional brief or a permission-cleared local clip set. Do not ask students to contact a real church, client or event organiser. Keep the revision notes as practice feedback, not claims about a real client. Any drone or public-space activity requires separate current legal and venue checks; this course does not provide those rules.

## Can you do these now?

1. What information should be agreed before filming begins?
2. Why should revision notes be time-coded and consolidated?
3. What is the difference between a revision and a new scope request?
4. Why is attendance at an event not automatic permission to publish a person's image?
5. What should a delivery note state?
