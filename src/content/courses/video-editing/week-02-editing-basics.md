**Goal:** Turn the Week 1 clips into a coherent 30-second rough edit with clean cuts and a checked export.

## Learning Objectives

- Identify the media area, viewer, timeline, tracks and inspector or properties area in an editor.
- Create a project that matches the footage and save it in the correct project folder.
- Import copies of the Week 1 clips, select usable moments and build a rough sequence.
- Trim, split, ripple-delete and close gaps without losing the source footage.
- Use pacing, cut-on-action and simple reframing to support a 30-second story.
- Export and review a draft, record limitations, and preserve a separate project version.

## Lessons

### Lesson 1: The editing interface

Most editing applications arrange the work into familiar regions. A **media pool** or project bin lists clips and other assets. A **viewer** or preview shows a source clip or the assembled result. A **timeline** places clips in order over time. **Tracks** separate picture, dialogue, music, titles and effects. An **inspector** or properties panel changes the selected item's settings. The names and layout vary, but the roles are similar.

Before editing, locate the project name, save indicator, media list, preview, timeline and export command. If the display looks different from a tutorial, search the app's current help rather than guessing. You can learn a concept without memorising a menu location.

Create a project in `04-Projects` and save it immediately with a clear name. Set the project frame size and frame rate to match the intended source and output where practical. Do not mix multiple formats without a reason. If you have vertical and horizontal takes, choose the intended delivery shape for this assignment, then check whether the other orientation can be used without awkward cropping.

### Lesson 2: Importing and selecting footage

Import copies or references media inside the editor; it should not replace or erase the camera originals. Start with a small copy of the clips in `01-Raw`. If the app offers a choice between copying media into a managed project or linking to a file, understand where the file will live before confirming. Keep the original folder unchanged and do not disconnect a drive while the project is open.

Review each clip and note the strongest usable section. You can make a simple paper log:

| Clip | Start / end moment | Useful detail | Limitation |
|---|---|---|---|
| Establishing view | | | |
| Process shot | | | |
| Close-up | | | |

Choose moments that show a beginning, a useful action and a result. A technically imperfect but meaningful shot may be more useful than a polished shot that does not support the story. Exclude footage that reveals private information, includes someone without permission, or makes an unverified claim.

### Lesson 3: Timeline, split and trim

The timeline is a visual plan for time. Place the clips in a sequence that makes the viewer understand what is happening. **Trimming** shortens a clip by moving its beginning or end. **Splitting** creates separate pieces from one clip, often so a middle section can be removed. The original source file remains unchanged when you edit non-destructively, but the exact behavior depends on the app; verify before using a destructive command.

To remove a pause, position the playhead at the start of the unwanted section, split, move to its end, split again, select the middle piece and delete it. Some apps leave a gap; others close the gap automatically with a ripple action. Inspect the result. If clips move unexpectedly, undo once and choose the intended delete behavior. Save a version before experimenting.

Use the viewer and timeline together. Play across each edit point, not just the first frame after a cut. Look for an accidental black frame, audio pop, repeated action or abrupt change in direction. Zoom the timeline enough to select the correct point but not so much that you lose the sequence's overall shape.

### Lesson 4: Choosing the best moments and making a rough cut

A **rough cut** is an early assembly focused on order and meaning, not polish. Start with the clearest shot that establishes the subject. Follow with the action, supporting details and a satisfying ending. Keep only the material needed to make the idea understandable.

The assignment is 30 seconds, but time is not a reason to cut every shot to the same length. A fast action may need a short view; a viewer may need longer to read or understand a detail. Watch the sequence once without stopping. If you cannot explain the story in one sentence, revise the order or remove distractions.

Keep a working version rather than overwriting the project. Use version labels such as `rough-v01` and `review-v02`. A version note can describe one change: "Moved the close-up before the finished item; shortened a pause." This helps a learner or client understand what changed.

### Lesson 5: Pacing, rhythm and cut on action

**Pacing** is the speed at which information and emotion unfold. A food preparation sequence may use a few concise actions followed by a longer shot of the finished item. A calm craft demonstration may need slower cuts. Music is not part of this week's assignment; use shot length, sound continuity and movement to create rhythm.

**Cut on action** means changing the shot while a movement is continuing, such as a hand reaching in one shot and completing the placement in another. The continuous action can make the cut feel natural. Match the direction and timing. If a movement jumps backward or seems to happen twice, use another take or cut before the motion begins.

A **jump cut** removes time within a similar-looking shot, which can create an abrupt visual jump. It may be intentional for a fast social edit, but too many can be distracting. Cover an unwanted jump with relevant B-roll, use a different camera distance, or leave a longer continuous action. Do not insert unrelated footage only to hide an edit.

A **J-cut** is an editing idea where the next scene's sound begins before its picture appears. An **L-cut** lets current sound continue after the picture changes. They can make interviews and stories flow, but this week you may practise the concept using natural sound only. Audio controls vary by app; do not assume the same editing command exists in all versions.

### Lesson 6: Speed, freeze frames, crop and stabilisation

Speed changes alter how quickly action plays. A speed-up can compress a repetitive process; a slow-down can highlight detail. Use them sparingly and check whether the result looks smooth. The source frame rate and editor method affect quality. A **freeze frame** holds a selected image, which can help explain a detail but may feel static if held too long.

**Reframing** changes crop, scale or position. It can adapt a wide shot to a vertical frame, but cropping removes part of the image and enlarging may reduce detail. Keep faces, hands and important objects visible. Check the whole frame on a phone-sized preview. Avoid cropping out someone or something in a way that changes the meaning.

Some editors provide **stabilisation**. It may crop or warp edges and can fail on rapid motion; test a short copy and compare with the original. A shaky take is not always fixable. For this week's requirement, make one speed change and one reframed shot, then document if the device or app does not support the feature. An equivalent alternative is to choose a different clip and explain the limitation.

### Lesson 7: Transitions and simple storytelling

A straight cut is the default transition because it preserves pace and avoids distracting the viewer. A dissolve blends two pictures and can suggest a passage of time or gentle change. Use it when the story benefits; do not add a transition to every edit. Wipes, spins and decorative effects can draw attention away from the subject.

Think of the 30-second piece as a small story: **setup** (what are we seeing?), **process** (what happens?), **result** (what changed or was made?) and **close** (what should the viewer remember?). A title can identify the fictional exercise, but it cannot repair a confusing sequence. Keep factual statements limited to what the footage supports. Fresh Bites is fictional; do not invent customer testimonials, prices, delivery claims or outcomes.

### Lesson 8: Save, back up and export a quick draft

Save the editor project to `04-Projects` and keep any required linked media together. Some apps save automatically; still verify the save indicator and project path. Before closing, check that the project can reopen and that media is not offline. Use the edit-review checklist to inspect the draft.

Export a short review copy in a common format offered by the editor. Choose an aspect ratio that matches the intended version. Do not select a resolution, codec or bitrate from memory if the destination has current requirements; check them before final delivery. After export, play the file from beginning to end, check sound and cut points, and note the actual file size. The export can differ from the timeline, so a rendered review is essential.

Keep a separate review export in `05-Exports` and project file in `04-Projects`. Do not replace the source clips with an export. If data is limited, review locally instead of uploading. The prompt for this week requests a 1080p output; if a device cannot produce it reliably, record the limitation and show a readable local review rather than faking a result.

## Common Mistakes

- Moving or deleting source clips while an editor is linking to them.
- Assuming the timeline is saved because the preview still plays.
- Deleting a clip without checking whether the gap closes or other tracks move.
- Adding transitions and speed effects before the rough sequence makes sense.
- Cropping a vertical version until the subject or context is lost.
- Exporting only the timeline and never watching the actual file.
- Using a tutorial's exact shortcut without checking the current app version.

## Practice Exercises

1. Identify the media pool, viewer, timeline, tracks and properties panel in your editor.
2. Import copies of three Week 1 clips and confirm the originals remain unchanged.
3. Create a 10-second sequence with one clean split and a gap-free delete.
4. Make two versions of the same sequence with different clip orders; explain which is clearer.
5. Create one cut-on-action edit and review it at normal speed.
6. Make one speed change and one crop/reframe; compare each with the original.
7. Export a short draft, play it on a second device or player, and write down one issue.
8. Save a new project version and reopen it to check that media is online.

## Weekly Assignment (Due Before Week 3)

Edit a 30-second "A Day at Fresh Bites" video, or a video about your own permitted subject, using the Week 1 clips. Include at least 12 cuts, one speed change and one reframed shot. Do not add music yet. Export at 1080p if the chosen device and editor support it reliably; otherwise document the constraint and submit the best playable review export available. Include a 100-word edit note explaining the sequence, one decision and one improvement.

**Grading guide:** cut quality 35%, pacing 30%, technical export 15%, story clarity 15%, edit note 5%.

**Definition of done**

- [ ] The video is approximately 30 seconds and has at least 12 deliberate cuts.
- [ ] One speed change and one reframed shot are visible or a limitation is documented.
- [ ] The sequence has a clear opening, process and ending.
- [ ] No music, unpermitted footage or unsupported claims are included.
- [ ] The export plays to the end and the project/source files remain organised.
- [ ] The edit note is about 100 words and names one next improvement.
