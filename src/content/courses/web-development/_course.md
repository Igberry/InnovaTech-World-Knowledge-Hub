**Learn to build real websites and web apps — starting from absolute zero.** Over 12 weeks you will
go from your first line of HTML to a deployed React app backed by a real database, building one
growing project the whole way so your skills stack into a portfolio you can show.

## Who this is for

Complete beginners. You need basic computer skills (open a browser, save a file) and a willingness to
practise. No coding experience is assumed. Every tool is free, and we include fallbacks for weak
laptops and unreliable power or internet.

## What you'll be able to do

- Build responsive, accessible websites with HTML and CSS
- Make pages interactive with JavaScript, and call real web APIs
- Use Git and GitHub like a professional, and deploy for free
- Build a React app with modern tooling (Vite + Tailwind CSS)
- Save and protect data with Supabase (a database and user login)
- Publish a **5-project portfolio** and prepare for freelance or remote work

## One running project

Everything you build is for one fictional business — **Yenagoa Fresh Bites**, a small restaurant and
takeaway. As you learn, the site grows from plain pages into a full app with a menu, cart,
reservations and a database. By the end you have a complete, deployed project (plus four more) in your
portfolio. The content kit (brand, menu data, colours, placeholders) is in the files for Week 1.

## The 12-week plan

| Week | Topic | Main deliverable |
|---|---|---|
| 0 | Setup guide | A working developer environment |
| 1 | How the web works, HTML & Git/GitHub | First page published on GitHub Pages |
| 2 | Semantic HTML, forms & accessibility | Multi-page HTML site |
| 3 | CSS fundamentals | Styled site with a brand palette |
| 4 | Layout (Flexbox, Grid) & responsive design | **Project 1:** responsive site, live |
| 5 | JavaScript I: fundamentals | Practice programs + a menu data module |
| 6 | JavaScript II: the DOM & events *(mid-course checkpoint)* | Interactive menu filter and cart |
| 7 | JavaScript III: async, APIs & storage | **Project 2:** interactive app, live |
| 8 | Modern tooling: npm, Vite, Tailwind & deployment | Site rebuilt with Vite + Tailwind |
| 9 | React I: components, props & state | Menu and cart as React components |
| 10 | React II: routing, forms & data | **Project 3:** React multi-page app, live |
| 11 | Databases & authentication with Supabase | **Project 4:** reservations saved to a database |
| 12 | Capstone, portfolio & freelancing/remote readiness | Capstone + portfolio + profiles live |

## How mentoring works

Each week has a **90-minute in-person mentoring session**: we review the past week, code live together,
pair on a tricky part, review your committed work, and brief the next assignment. You do the bulk of
the work on your own between sessions — that independence is part of becoming a developer.

## Assessment & certification

| Component | Weight |
|---|---|
| Weekly assignments (Weeks 1–11) | 40% |
| Mid-course checkpoint (end of Week 6) | 15% |
| Capstone project and presentation (Week 12) | 30% |
| Attendance, consistency & Git commit history | 15% |

A **completion certificate** is awarded at **70% or above** overall.

## Honest outcomes

Beginners do not become fully job-ready in 12 weeks — that takes sustained practice beyond the course.
What this course gives you is real: a **deployed portfolio of five projects**, a professional GitHub
profile, the habit of building and shipping, and a clear plan for applying. We measure success by
**work you can show and consistent practice**, never by promises. We do not guarantee a job or any
income.

## Tools (all free)

VS Code, Chrome or Edge, Git & GitHub, Node.js, Vite, Tailwind CSS, React, and a free Supabase account
you create yourself in Week 11.

## Facilitator Notes

Pace to the learner, not the calendar — it is fine to spend two sessions on a hard week (CSS layout,
the DOM, React state, Supabase RLS are the usual sticking points). Insist on typing code (not pasting)
for the first six weeks, and check the Git commit history every week as a signal of consistent effort.
Keep the full solutions in the private `_facilitator/` folder, never in the public repo.
