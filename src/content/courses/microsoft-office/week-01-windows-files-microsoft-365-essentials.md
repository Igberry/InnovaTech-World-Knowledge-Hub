**Goal:** By doing, not reading, build a file routine you trust - find anything fast, name it so future-you understands it, and share it without leaking private data. You will tidy 15 files with your own hands this week.

## What you'll be able to do

- Find any app, setting or file using Start, search and File Explorer
- Create folders and copy, move and rename files without losing track
- Name files date-first so they sort and make sense a year later
- Tell local storage, cloud storage and sync apart in one sentence each
- Share a view-only OneDrive link and then remove it
- Spot a fake sign-in page and a risky USB before they bite you

## Before you start (about 10 minutes)

- Open File Explorer with **Win+E** and make one empty test folder.
- Download the dummy files list, folder template and shortcuts cheat sheet.
- Warm-up: save a harmless text file, then rename it with **F2**. You just did the two actions this week is built on.
- Optional 10-minute video: search YouTube for **"Kevin Stratvert Windows 11 File Explorer basics"** if you want a visual tour first.

## Try it 1 - Find anything in Windows

**Why it matters:** the desktop is a workspace, not a filing cabinet. Searching beats clicking through menus every time.

**Do this now:**
1. Press **Win+S** and launch Word, then Settings, then File Explorer - all from search.
2. Pin one app you use often to the taskbar, then keep the desktop clear.
3. On a shared PC, check whose Windows account is active before you save or sign in.

**You've got it when:** you can open any app or setting by typing its name, without hunting.

## Try it 2 - Master extensions and file types

**Why it matters:** the letters after the dot tell Windows which app owns the file. Renaming them does not convert anything.

**Do this now:**
1. In File Explorer, turn on **View then Show then File name extensions**.
2. Look at the five types below and say what each is for out loud.
3. Try renaming a copy of a `.csv` to `.xlsx` - open it and watch it stay broken. Converting means opening in the right app and using **Save As**.

| Extension | Common use | The catch |
|---|---|---|
| `.docx` | Editable Word document | Keeps structure and formatting |
| `.xlsx` | Excel workbook | Holds formulas, sheets and charts |
| `.csv` | Plain tabular data | No formatting or formulas |
| `.pdf` | Portable viewing copy | Usually not the best editable source |
| `.zip` | Compressed archive | Extract before you use its contents |

**You've got it when:** you can explain why `report.csv` renamed to `report.xlsx` is still not a real workbook.

## Try it 3 - Copy, move and rename safely

**Why it matters:** moving the wrong file is how work disappears. A safe routine makes it boring instead of scary.

**Do this now:**
1. Build the supplied folder structure from the template.
2. Copy a harmless file into it, then confirm both copies open before deleting anything.
3. To move a file: select, cut, open the destination, paste, then check it arrived.
4. Sort a folder by **Name**, **Date modified** and **Type** to see how each view helps.

**You've got it when:** you copy-then-verify by habit, and never delete an original on faith.

## Try it 4 - Rename all 15 dummy files (the main event)

**Why it matters:** `new`, `final-final`, `document (4)` tell you nothing. A date-first name sorts itself and explains itself.

**Do this now:**
1. Open the dummy files list and use this pattern on every one:

```text
YYYY-MM-DD_Client_Document_v01.ext
```

For example, `2026-11-12_FreshBites_SupplierLetter_v01.docx` is a fictional practice name. Date sorts chronologically, the project is visible, the purpose is clear, the version is easy to bump.
2. Drop each renamed file into the right folder: originals in `00_Inbox_Originals`, exports in `07_Exports`.
3. Never put a real customer's sensitive details in a filename. No slashes - Windows forbids them.

**You've got it when:** all 15 files are renamed, placed, and sort in a sensible order on their own.

## Try it 5 - Zip, unzip and handle a USB without fear

**Why it matters:** archives and USB drives are where surprise malware hides.

**Do this now:**
1. Make a ZIP of a practice folder, then **Extract all** into a new folder.
2. Do not run a program just because it rode along inside an archive.
3. Only plug in a USB you trust, scan it with current security software, and never open a found device. The [Cybersecurity Foundations course](/courses/cybersecurity/) goes deeper on safe device habits.

**You've got it when:** you can extract an archive and say what you would refuse to open and why.

## Try it 6 - Share a OneDrive folder, then take it back

**Why it matters:** a sharing link is a permission, not just a URL. The skill is sharing narrowly and cleaning up after.

**Do this now:**
1. Make a practice folder with no real data and share it with a second account you own or an authorised training address.
2. Choose **Can view**, not edit. Pick named people over "anyone with the link".
3. After the exercise, remove access.
4. Open OneDrive version history on a file and note that deleted items sit in a recycle bin for a limited time, depending on account policy.

> **Privacy:** Use only the fictional practice folder. Confirm who can open it, and remove access when the exercise ends. A link that works for "anyone" is not private.

**You've got it when:** you have shared view-only and then removed the share, with no real data involved.

## Try it 7 - Screenshot, PDF and account safety

**Why it matters:** a screenshot can leak a notification; a fake sign-in page can steal a password.

**Do this now:**
1. Capture only your practice note with **Win+Shift+S**, then check nothing private is in frame.
2. Export a short note to PDF and reopen it to confirm the layout holds.
3. Before entering a password, read the address bar and confirm it is Microsoft's real sign-in domain. A familiar logo proves nothing.
4. Turn on two-step verification where available. Legitimate support never asks you to read a code aloud.

**You've got it when:** you can name two signs of a fake sign-in page and share a screenshot that exposes nothing extra.

### Watch out for

- Renaming an extension instead of converting or exporting
- Editing the only copy of a starter, or treating sync as a backup
- Sharing with "anyone with the link" when a named view-only share would do
- Moving files before confirming they arrived
- Clicking a sign-in link from an unexpected email or text
- A screenshot that exposes a private account, message or notification

## Facilitator Notes

Use a device with no private files visible during screen sharing. Do not ask learners to disclose passwords, verification codes or personal Microsoft account information. Provide an offline equivalent for anyone without an account or stable connection. Verify that every learner can locate a local copy before discussing OneDrive recovery. Encourage learners with assistive technology or managed devices to use their normal settings rather than changing them for the class. The dummy files and fictional case are for practice; do not request that learners upload personal documents.
