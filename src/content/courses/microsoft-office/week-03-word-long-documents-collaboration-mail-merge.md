**Goal:** Build a navigable multi-page proposal, review it the way a real team does, and run a mail merge to ten records - all by doing, on fictional data only. These are the Word skills that make you look senior.

## What you'll be able to do

- Steer a long document with the Navigation pane and heading styles
- Insert an automatic table of contents, captions and page numbers that update themselves
- Use section breaks for a clean cover and flexible page layout
- Save a reusable template so you never rebuild from scratch
- Review with Track Changes and comments, and accept or reject edits on purpose
- Preview a mail merge from ten records without sending a thing

## Before you start (about 10 minutes)

- Open the proposal starter, the ten-record CSV and the mail merge letter.
- Warm-up: apply **Heading 1** to two section titles in the proposal, then open the Navigation pane (**Ctrl+F**) and click between them. You now have a document map.
- Optional 10-minute video: search YouTube for **"Kevin Stratvert Word table of contents headings page numbers"**.

## Try it 1 - Map a long document with headings

**Why it matters:** a long document without a heading map is impossible to steer or reorganise.

**Do this now:**
1. Apply **Heading 1** to each main proposal section and **Heading 2** to subsections.
2. Open the Navigation pane and jump between sections by clicking headings.
3. Drag a heading to reorder it, then check tables and captions moved with the right text.

**You've got it when:** every section shows in the Navigation pane in a sensible order.

## Try it 2 - Add an auto table of contents and captions

**Why it matters:** an automatic contents list and captions update on their own; a typed one goes stale the moment you edit.

**Do this now:**
1. From **References**, insert an automatic table of contents.
2. Change a heading, then update the table and watch it correct itself.
3. Add a caption like "Table 1: Fictional service-planning assumptions" and cross-reference it in a paragraph.

**You've got it when:** you edit a heading, hit update, and the contents fixes itself.

## Try it 3 - Section breaks, covers and page numbers

**Why it matters:** section breaks let one page look different from the rest - a clean cover, a landscape appendix.

**Do this now:**
1. Insert a section break before the proposal body.
2. Turn on **Different First Page** for a clean cover.
3. Add automatic page numbers and confirm the first body page has the number you want. If numbering jumps, check **Link to Previous**, not a typed number.

| Break | Starts a new page | Can change headers, orientation or numbering by section |
|---|---|---|
| Page break | Yes | No |
| Section break | Depending on break type | Yes |

**You've got it when:** your cover has no page number and the body numbers start correctly.

## Try it 4 - Save a reusable template

**Why it matters:** a template means you start new documents in seconds, not hours.

**Do this now:**
1. Strip a clean proposal copy of all sample names and business details.
2. Keep the styles, heading levels, a standard table and a footer with a version placeholder.
3. Save it as a template, then create a new document from it and immediately **Save As** a new name so you never overwrite the template.

**You've got it when:** you can spin up a fresh, correctly styled proposal from your template.

## Try it 5 - Review like a team with Track Changes

**Why it matters:** this is how edits move between people without anyone losing work or context.

**Do this now:**
1. Turn on **Track Changes** before editing a copy, not after.
2. Make a small edit and add a comment with a question.
3. Use **Compare** on two copies to see differences when history is missing.
4. Accept or reject changes one at a time - do not hit "Accept All" just to clear the colour.

**You've got it when:** you can show a reviewed copy with edits accepted or rejected on purpose.

## Try it 6 - Run a mail merge (preview only, never send)

**Why it matters:** mail merge personalises one letter to many people - and can repeat a mistake ten times if you skip the preview.

**Do this now:**
1. In the Mailings tab, start a letter merge and select `customers-list-10.csv`.
2. Insert fields such as FirstName and PreferredPackage.
3. Preview all ten records and check what an empty field does to the sentence.
4. Finish to a new merged document for review, then close without sending.

> **Warning:** Preview but do not send this practice campaign. The sample addresses use the reserved `.invalid` domain and are not real recipients.

**You've got it when:** all ten records preview cleanly and no message leaves your machine.

### Watch out for

- Typing a contents list manually and forgetting to update it
- Using page breaks where section breaks are needed for headers or numbering
- Accepting every tracked change without reading it
- Merging a real customer list, or sending practice messages
- Assuming a protected form is encrypted or private
- Sharing with a broad link when a named, view-only one is enough
- Treating the accessibility checker as a substitute for a human read

## This week's build: a real business proposal plus a mail merge

Using `proposal-content.md`, build an **eight-page-or-longer proposal** for the fictional catering contract with:

- A generated, updated table of contents and a clear heading structure
- At least one captioned table, automatic page numbers and a section break
- All sample amounts and assumptions labelled as fictional

Then produce a **mail merge** of the promotional letter to the ten fictional records as a review document (do not send). Complete one Track Changes round with your mentor and include the reviewed copy or a screenshot of the review state.

| Criteria | Weight |

### Definition of done

- [ ] The proposal has eight or more pages and a working, updated table of contents.
- [ ] Headings, page numbers, section break and table caption are present and readable.
- [ ] All sample amounts and assumptions remain labelled as fictional.
- [ ] Ten merge records preview correctly; no practice letter is sent.
- [ ] One review round shows tracked edits or a documented Compare result.
- [ ] The final copy is checked for accessibility, sharing permissions and private metadata.

### Mid-Course Checkpoint (end of Week 3, 90 minutes)

A supervised, hands-on checkpoint using fictional material. It contributes 15% of the course assessment.

1. **0-25 min:** repair a deliberately messy short document with styles, consistent spacing and a clear table.
2. **25-55 min:** create a short structured document with an automatic table of contents, one captioned table and page numbers.
3. **55-85 min:** connect a small fictional recipient list, insert a merge field and preview a simple letter merge - do not send.
4. **85-90 min:** save the files with clear names and explain one quality or privacy check.

The facilitator uses the same checklist for each learner and considers the result in the context of the learner's available app version.

## Extra quick wins (optional)

- Run the accessibility checker on your proposal and fix the top three findings.
- Add a simple fillable form control (text field or drop-down) with fictional entries.
- Use **Check for Issues** to find author names or tracked changes hiding in the metadata.

## Facilitator Notes

Prepare the checkpoint from fictional text only. Confirm that learners are in a review copy before editing. Do not collect or display actual customer lists, account identifiers or email addresses. If the learner's version lacks a feature, accept a demonstrated equivalent and note the limitation rather than requiring a purchase. During the track-changes round, ask the author to explain a decision; do not silently rewrite the learner's work. Allow the full 90-minute checkpoint in a quiet setting with accessible instructions.
