## Part 1: The Capstone Project

### Requirements
Choose **one** option and agree it with the facilitator at the start of Week 11 (so the student has time):

| Option | Description |
|---|---|
| **A. Real local data** | Analyse real data from a local business (with permission). Examples: a shop's sales, a school's results, a church's attendance and giving, an NGO's programme data. **Anonymise personal information.** |
| **B. Public dataset** | A new Kaggle or open-data dataset (different from Portfolio Project 1) |
| **C. Business case** | A fictional case with a clearly defined business problem, built on NaijaMart data with a new angle (e.g., "How should NaijaMart reduce returns and increase repeat purchases?") |

> **Privacy:** never publish real customer names, phone numbers, or financial details. Get written permission when using a real business's data.

### Capstone must demonstrate
| Skill | Evidence |
|---|---|
| Asking the right question | Clear problem statement and 3 to 5 specific questions |
| Data cleaning | Documented steps (Excel, SQL, Python, or Power Query) |
| SQL | At least 5 queries (joins and aggregations or CTEs) |
| Python | Cleaning, analysis and charts in a notebook |
| Power BI or Excel | An interactive dashboard |
| Communication | A 2 to 4 page report plus a 10 to 15 minute presentation |

### Capstone structure (the "Case Study")
1. **Business problem** (who needs this and why)
2. **Data** (source, size, limits, privacy notes)
3. **Approach** (tools and steps)
4. **Cleaning** (what was wrong, what you did)
5. **Analysis and findings** (with visuals)
6. **Recommendations** (specific, measurable, tied to the evidence)
7. **Limitations and next steps**

### Capstone checklist
- [ ] Question defined before analysis starts
- [ ] Raw data preserved; cleaning documented
- [ ] Numbers reconcile across tools
- [ ] Every chart has an insight title
- [ ] Recommendations are actionable
- [ ] README explains how to reproduce the work
- [ ] Spell-checked, with no private data exposed

## Part 3: Get Hired Remotely

### Position yourself
A common beginner mistake is *"I am a data analyst looking for opportunities."* Instead be specific:
> *"Entry-level data analyst | Excel · SQL · Python · Power BI | I build dashboards that show retail businesses where they lose money."*

Pick a **target niche** (retail/e-commerce, education, NGOs/health, finance, marketing analytics) and mention it in the headline.

### LinkedIn
- Professional photo, banner, and headline (as above)
- **About:** 4 to 5 short lines: who you help, tools, a result, a call to action
- **Featured:** pin your GitHub and best dashboard
- **Projects:** add all five, with links
- **Skills:** Excel, SQL, Python, pandas, Power BI, Data Cleaning, Data Visualisation, Statistics
- Post a short insight from each project (builds visibility)

### Where to look
| Type | Where |
|---|---|
| Freelance | Upwork, Fiverr, Freelancer |
| Remote jobs | LinkedIn Jobs, OnlineJobs.ph, We Work Remotely, Remote OK, Remotive |
| Local | LinkedIn, company career pages (banks, telecoms, oil and gas services, NGOs), referrals from the facilitator's network |
| Practice | Kaggle competitions, public datasets |

> **Be careful with scams.** Never pay to get a job. Be suspicious of cheque payments, requests for equipment money, "training fees", or offers that skip any interview. Check the company's website and reviews.

### Writing a proposal for a data gig (template)
```
Hi [Name],

I read your post about [their problem, e.g., messy sales reports].
I'd help by [specific approach: clean the data in Excel/SQL, build a dashboard
that shows X and Y].

Here's a similar project I built: [link]. It [result].

I can deliver [specific deliverable] in [timeframe]. Could we do a 15-minute
call, or would you like to share a sample of the data?

Best,
[Name]
```
**Pricing:** research current rates for your region and experience on Upwork, then start with small fixed-price projects to build reviews. Never work for free on "test projects" that are actually real work.

### Interview preparation
**Technical topics:** Excel (lookups, pivots), SQL (joins, GROUP BY, window functions), Python (pandas basics), Power BI (DAX, modelling), statistics (mean vs median, outliers, correlation).

**Common questions:**
1. Walk me through a project you're proud of.
2. How do you handle missing or messy data?
3. How would you check whether a number in a report is wrong?
4. Explain a `LEFT JOIN` to a non-technical person.
5. Tell me about a time you found something surprising in data.
6. How would you explain these results to a manager?

**Answer framework (STAR):** Situation → Task → Action → Result.

## Graduation Session Plan (In-Person, 2 hours)
| Time | Activity |
|---|---|
| 0–10 min | Welcome and review of the 12-week journey |
| 10–60 min | **Capstone presentations**: each student presents for 15 minutes plus 10 minutes of Q&A from the facilitator (acting as client) |
| 60–85 min | **Mock interview**, one student at a time, using the question list above, with scored feedback |
| 85–100 min | Portfolio and LinkedIn review (screen share); final fixes |
| 100–110 min | Next 30 days plan: applications per week, learning goals |
| 110–120 min | Certificate presentation, photos, and testimonials |

### Presentation scoring rubric
| Criterion | Points |
|---|---|
| Clear problem and audience | 15 |
| Quality of analysis and accuracy | 25 |
| Visuals and clarity | 20 |
| Actionable recommendations | 20 |
| Delivery and handling questions | 20 |
